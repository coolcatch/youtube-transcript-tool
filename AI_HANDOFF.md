## 2. Architecture

```
Browser
 ├─ /                    Home (static). UrlForm validates the link client-side → /transcript?v=ID
 └─ /transcript?v=ID     Server component validates v → renders <TranscriptView> (client)
        └─ fetch /api/transcript?v=ID[&lang=xx]
                │  Vercel serverless function, Node runtime, maxDuration 30 s
                │  Response cached at the Vercel CDN (s-maxage=3600) on success
                ▼
        getTranscript()  src/lib/transcript.ts
          in-memory TtlCache (6 h, 200 entries, per instance)
          fetcher chain, first success wins:
            1. innertube   YouTube direct, free. BLOCKED on Vercel (datacenter IPs).
            2. thirdparty  Supadata API: PRODUCTION PATH (TRANSCRIPT_FALLBACKS=thirdparty + TRANSCRIPT_API_KEY)
            3. whisper     yt-dlp + speech-to-text (off; CLI/self-host only)
                ▼
        TranscriptResult JSON → the browser groups segments into paragraphs (format.ts)
        and builds Copy / TXT / SRT / VTT / JSON entirely client-side.
```

**Data model (`src/lib/types.ts`):**
- `Segment {start s, duration s, text}`
- `TrackInfo {languageCode, name, kind: asr|manual}`
- `TranscriptResult {videoId, title, author, lengthSeconds?, thumbnailUrl, language, languageName, isAutoGenerated, tracks[], segments[], source, fetchedAt}`
- `TranscriptError {code, status, tracks?}` with these codes:

| Code | HTTP |
|---|---|
| `INVALID_ID` | 400 |
| `VIDEO_UNAVAILABLE` | 404 |
| `NO_CAPTIONS` | 404 |
| `LANG_NOT_FOUND` | 404 |
| `BLOCKED` | 503 |
| `UPSTREAM` | 502 |
| `NOT_CONFIGURED` | 501 |

## 5. Known bugs and limitations
1. **Supadata quota → misleading error.** When the 100 monthly credits are used up, users see "YouTube didn't answer properly. Please try again." (`UPSTREAM` 502).
2. **No rate limit or auth on `/api/transcript`.** Anyone can burn the credits (see SECURITY_REVIEW F1).
3. **The language picker is limited on the Supadata path.** A default request (no `lang`) returns only the one language Supadata chose, so the picker is hidden. With `?lang=xx`, Supadata returns all `availableLangs` and the picker appears. Languages show as raw codes ("fr") instead of names. Each language switch costs a credit.
4. On the Supadata path, `isAutoGenerated` is always `false` and `lengthSeconds` is missing, so the length isn't shown.
5. Every uncached production request first tries YouTube direct, which is blocked and adds a small delay before Supadata is called. That's harmless but wasteful.
6. Cache keys include the raw query (`v=<url>` vs `v=<id>`, `format=`), so caching is less effective than it could be.
7. The in-memory cache is per serverless instance and resets on cold start.
8. Paragraph splitting is heuristic. Auto-captions without punctuation become blocks of about 900 characters.
9. No playlists or channels, no history, no AI summary, no CI workflow.
10. Whisper fallback: untested, and impossible on Vercel (it needs the yt-dlp binary, and files are size-limited).

## 6. Security concerns (details in SECURITY_REVIEW.md)
- ✅ The key is server-side only, there's no `NEXT_PUBLIC_` usage, the live JS bundles contain no secrets, and the git history is clean (gitleaks + a manual scan).
- ❌ **High:** credit exhaustion through the public API. Add a Vercel Firewall rate limit and/or a code-level limit and spend cap.
- ⚠️ Medium: the quota error message, cache-key normalisation, and the key possibly being available to Preview deployments.
- Low: missing CSP/security headers, upstream error detail in messages.

## 8. Instructions for future AI developers

1. `git clone https://github.com/coolcatch/youtube-transcript-tool && cd youtube-transcript-tool && npm ci`
2. Check that everything is green: `npm test && npm run lint && npm run typecheck && npm run build`.
3. Develop locally with `npm run dev`. On a home connection YouTube direct works, so you **don't need the Supadata key**. For UI work, use `TRANSCRIPT_FIXTURE_MODE=1` and `/transcript?v=fixture0001`.
4. To test the Supadata code path without spending credits, run a mock server and point `TRANSCRIPT_API_BASE_URL` at it, or mock `fetch` in Vitest (see `tests/innertube.test.ts` for the pattern).
5. Make changes on a **new branch**, add or adjust tests, update `CHANGELOG.md`, push and open a PR. Vercel builds a preview, and the bot comments the URL. **Lisa merges.**
6. Keep it minimal: no UI framework, no analytics. Read env vars only through `src/lib/config.ts`, and never use a `NEXT_PUBLIC_` prefix for secrets.
7. If production breaks after a merge, roll back. Fastest: Vercel → Deployments → last good deployment → **Instant Rollback** (on the Hobby plan this only goes back to the previous production deployment, and after it you need to promote or redeploy so auto-deploys resume). Permanent: open a PR with `git revert -m 1 <merge-sha>`. Never force-push.
8. If YouTube direct stops working locally for every video, update `ANDROID_CLIENT.clientVersion` in `innertube.ts` (yt-dlp's `INNERTUBE_CLIENTS['android']` is a good reference).
